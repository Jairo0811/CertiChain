## 2. Hallazgos

Severidad: **C** crítica, **A** alta, **M** media, **B** baja. Todos fueron reproducidos en `c77a14f`.

### Críticos

| # | Hallazgo | Evidencia | Corrección |
|---|---|---|---|
| C1 | Rate limiting con un único mapa por IP compartido entre políticas: cada login sumaba en el contador general **y** en el de login con distinto límite; tras ~20 peticiones generales el login quedaba bloqueado. | `security.ts`: `buckets` global, clave = IP. | Contadores aislados por política; `/auth` y `/verify` excluidos del límite general; mapa barrido y acotado. Tests en `security.test.ts`. |
| C2 | `X-Forwarded-For` leído directamente: cualquier cliente evadía el límite falsificando la cabecera. `trust proxy` fijo en `1`. | `security.ts:21`, `app.ts:126`. | Clave = `req.ip`; `TRUST_PROXY` explícito (vacío por defecto; `uniquelocal` en Compose detrás de nginx). |
| C3 | La transacción blockchain se enviaba **antes** de persistir el certificado; si la persistencia fallaba quedaba evidencia on-chain huérfana, y un reintento emitía un duplicado (el contrato usa `nonce`, ids distintos). | `app.ts:259-269`; test de contrato `assigns distinct ids…`. | *Persist-first*: registro `pending/submitting` → tx hash guardado en cuanto el RPC acepta → activación tras confirmación. `POST /certificates/:id/anchor` reconcilia por recibo o por evento y **nunca reenvía** una tx enviada. |
| C4 | Verificación «criptográfica» circular: web y móvil pedían el hash a `/verify/:id/evidence` y lo reenviaban a `/verify/:id`; `hashMatches` era siempre verdadero y la UI hablaba de integridad. | `PublicVerify.tsx`, `AdminValidationBridge.tsx`, `mobile/lib/api.ts`. | `/verify/:id` sin hash = consulta de estado con `integrity: "not_evaluated"`. Verificación opcional de un PDF local con Web Crypto (solo se envía el SHA-256). |
| C5 | Revocar una credencial anclada sin RPC configurado la marcaba revocada solo off-chain (divergencia silenciosa); lo mismo para borrado y cambio manual de estado. | `app.ts:336`, `certificateStatusRoutes.ts:47`. | Modo de evidencia explícito; credenciales on-chain: 503 si no hay blockchain, revocación on-chain primero, nunca borrado ni reactivación. |

### Bajos

- Fechas `DATE` de PostgreSQL convertidas con `toISOString()` (posible desfase de un día) → formateo sin conversión UTC.
- Indicador «Conexión local segura» sin relación con el transporte real → muestra HTTPS solo cuando lo es.
- Credenciales demo visibles en el login de cualquier build → solo en desarrollo o con `VITE_DEMO_MODE=true`.
- Revocación sin confirmación en la UI → confirmación explícita (motivo y palabra de confirmación para on-chain).

## 3. Decisiones de diseño relevantes

- **Modos de evidencia**: `on-chain` (id bytes32 del contrato), `demo` (dataset ilustrativo), `off-chain`. Solo `on-chain` (o anclaje en curso) queda gobernado por blockchain.
- **Reactivación off-chain**: se conserva la funcionalidad existente (revocada → vigente) solo para off-chain/demo y ahora exige un motivo auditado.
- **Verificación**: `outcome` explícito (`valid`, `pending`, `revoked`, `not_found`, `integrity_mismatch`, `blockchain_mismatch`, `blockchain_not_configured`, `blockchain_unavailable`). `valid` se mantiene por compatibilidad.
- **Sin React Router**: cuatro pantallas sin rutas anidadas; un enrutador mínimo por `pathname` da enlaces profundos y navegación atrás/adelante sin dependencia nueva.
- **Sin librería de gráficos**: tres gráficos simples en SVG con tablas ocultas accesibles.

## 5. Pendiente / no validado en este entorno

- **Imágenes Docker**: no hay daemon Docker en el sandbox; se validaron `docker compose config` (base y prod) y la sintaxis de `nginx.conf`, pero no `docker build` ni `compose up`.
- **Descarga de `solc`**: `binaries.soliditylang.org` no es accesible aquí; los contratos se compilaron con `solc` 0.8.24 de npm mediante una configuración local no versionada. En GitHub Actions la descarga normal funciona.
- **GitHub Actions**: no se ejecutaron en este entorno; deben confirmarse en el PR.
- **IPFS real, redes públicas (Sepolia/Amoy/Polygon) y dispositivo físico**: no se usaron; no hubo despliegues ni wallets reales.
- **Avisos restantes de `npm audit`** (2 altos, 11 moderados, 2 bajos en producción): `zod` (requiere Zod 4) y la cadena de `@expo/cli` (requiere cambio mayor de Expo). Mitigación de Zod: los esquemas de CertiChain no validan colecciones de tamaño arbitrario y el JSON está limitado a 32 KB.
- **Rate limiting y bloqueo por certificado** son en memoria (una instancia). Varias réplicas requieren almacén compartido (Redis) y bloqueo en base de datos.
- **Retención de auditoría**: cada verificación pública genera un evento; se acotaron las lecturas pero falta una política de retención/archivado.
